Принцип работы декодера Auro
============================
Сводка по native Auro-Codec (PCM/WAV) и AuroCX (MP4).
Дата: 2026-07-16.


------------------------------------------------------------------------------
1. Два разных пути
------------------------------------------------------------------------------

Auro-Codec (classic / «auro native»)
  - Контейнер: WAV/FLAC PCM24.
  - Carrier — не «чистый bed без height»: при encode height mix’ится в surround PCM.
  - Декодер unmix’ит до 3 каналов из одного carrier-канала (Extrapolate + residuals
    в младших битах PCM) → discrete height с разделением.

AuroCX
  - Контейнер: MP4 трек a3ds + конфиг acxd.
  - Нет PCM-carrier для height: все каналы — сжатые audio streams (AWC/LFE)
    плюс SASC для resample/routing.
  - Путь: авто по контейнеру (MP4 a3ds → CX; иначе classic). Диагностика: --probe.


------------------------------------------------------------------------------
2. AuroCX: как хранится звук
------------------------------------------------------------------------------

Структура:

  MP4
   └─ трек a3ds + конфиг acxd (layout, sample rate…)
       └─ Access Units (кадры)
           └─ sync A3 DC 0D ED
               └─ XOR/VLQ blob (segment 1)
                   ├─ Schema: программа, beds/objects, потоки
                   └─ PDU vector: сжатые куски аудио

Звук не лежит как PCM. Типы PDU:

  AWC lossless     — LPC + энтропийно сжатые residuals (+ ICC между каналами)
  AWC transparent  — near-lossless: residuals с ErrorScaler
  LFE              — НЧ-поток + интерполяция (факторы 40…640)
  SASC             — enhancement: resample/gain/routing, не синтез height

Типичная группировка корпуса: несколько AWC-групп + иногда LFE + SASC.

Цепочка декодера:

  MP4 → AU → Schema → PDUs
    → AWC (entropy → LPC → ICC)
    → LFE (residual → upsample)
    → streams → SASC → PCM24 WAV

Особенности:
  - Первый AU — полная schema; дальше часто delta (common=1).
  - Потоки логические; маппинг bed→stream задаёт schema.
  - Обычно 1024 сэмпла на stream на AU.
  - LPC-история сбрасывается на AWC-кадр; между AU живёт в основном LFE-фильтр.


------------------------------------------------------------------------------
3. Динамические объекты с координатами
------------------------------------------------------------------------------

В schema AuroCX заложено:
  - object_groups / objects / switch_groups
  - positions (x, y, z), 8 или 16 бит на ось
  - spreads, gains, zone_exclusion
  - позиции по subblock (динамика: absolute или delta)
  - default_object_position на уровне программы

Парсер (--probe) это читает.

На корпусе из 7 MP4: beds=1, object_groups=0, objects=0.
Это channel-bed контент (7.1 / 9.1 / 13.1), без летающих объектов.

В нашем декодере:
  - парсинг schema объектов — есть
  - рендер xyz → gains в динамики — НЕТ

В декомпиле libauro.so полный пайплайн есть:
  decode ObjectGroup/positions/spreads,
  render::plan::add_objects / visit_object_groups,
  update_panning_gains_, planner/selection, interactivity.


------------------------------------------------------------------------------
4. Native Extrapolate: восстановление высотных каналов
------------------------------------------------------------------------------

Принцип (classic Auro-Codec) — mix / unmix, не «угадай height из bed»:

  оригинал (bed + height stems)
          ↓ encode: controlled mix height → surround carrier
  WAV carrier 5.1/7.1 (уже содержит энергию height)
          +
  метаданные в LSB (ADOL + per-frame words + Golomb-Rice residuals)
          ↓ decode: Extrapolate unmix
  discrete FL… + HL/HR/… (100% separation по заявлениям Auro)

Bed-слоты на выходе часто совпадают с carrier (passthrough после обработки).
Отдельного height-трека в WAV нет — он восстанавливается unmix’ом.

Важно: Auro-Codec не опирается на корреляцию каналов как matrix-кодек.
Residuals несут в основном ошибку разделения/квантования, а не весь
независимый height «с нуля». Пример «внизу музыка, сверху вокал»:
при encode вокал уже запекается в carrier; без декодера слышен совместимый
surround (с вокалом), с декодером — разделение на слои.

Шаги:
  1. Carrier в DelayLine.
  2. Frame descriptor: source, mode, quant/scale, seeds.
  3. GolombRice_get_errors → signed residuals.
  4. Extrapolate_process(carrier, residuals) → height PCM.

Режимы Extrapolate:
  Mode 1 — один выход из source (scale/mask)
  Mode 2 — 2 канала из 1 source + 1 residual (типично для height-пар)
  Mode 3 — 3 канала из 1 source + 2 residuals; предиктор 4*last − 3*prev
           (до 3 PCM из одного carrier-канала — как в white paper)

Пример: 5.1 → 9.1 — HL/HR/HLS/HRS = native Extrapolate.

Это НЕ:
  - XinN / Auro-Matic (синтетика; см. §10)
  - AuroCX (height = AWC bed-streams + SASC)


------------------------------------------------------------------------------
5. Какие данные в мете для Native Extrapolate
------------------------------------------------------------------------------

Два слоя.

А) Глобальная ADOL-мета (layout):
  - layout_id           — целевой layout (напр. 5.1+4H)
  - carrier_layout_id   — что лежит в WAV
  - uses_mix3           — нужен ли Extrapolate mode 3
  - sync_sample / block_size — где начинается кадр

Б) Per-frame channel descriptor + packed words:
  - output channel id
  - prediction source ids (до 3)
  - Extrapolate mode (1/2/3)
  - quantization shift
  - scale indexes
  - Golomb-Rice: packed flags, bit width, base index
  - seeds (primary/secondary)
  - ctx words + stream words (таблицы + битстрим residuals)

Звуковые данные в мете — не PCM height, а:

  packed Golomb-Rice residuals (+ ctx table)

Схема:

  ADOL: layout / carrier / sync
    + frame meta: mode, sources, scale, quant, seeds, GR params
    + packed residuals
    + carrier PCM (из WAV)
    → height PCM


------------------------------------------------------------------------------
6. «Как это умещается в 4 бита?»
------------------------------------------------------------------------------

Не умещается в 4 бита одного сэмпла.
Это side-channel из нескольких младших бит × много сэмплов.

В 24-bit PCM в младшие бит-плоскости вшивается поток:

  сэмпл₀: биты 0..m-1
  сэмпл₁: биты 0..m-1
  …
        ↓ mux
  битстрим меты (ADOL + frame words + Golomb-Rice residuals)

Mux берёт маски 1, 2, 4… (биты 0, 1, 2…); параметр m (обычно ≥ 3).
Sync: 16 единиц подряд в LSB.

Ёмкость блока ≈ block_size × m бит (минус sync/CRC).
Параметр m в sync ≥ 3 и может быть заметно больше (в коде до ~14).

Пример: блок 1024, m=3 → ~3072 бит ≈ 3 кбит на канал на кадр.
Это НЕ 3 kbps: при 48 kHz кадр ≈ 21 ms → ~140+ kbps side-info
на один carrier-канал. Каналов несколько; плюс quant/scale (near-lossless).

Почему хватает даже при «разном» bed и height:
  1. Encode — mix/unmix: энергия height уже в carrier (§4).
  2. В LSB — сжатые residuals разделения + параметры, не PCM height.
  3. При нехватке бюджета энкодер сильнее квантует (rate–distortion).
  4. Для полностью независимых high-bitrate потоков без LSB-PCM — AuroCX.

(В white paper Auro-Cx для PCC упоминают ~3 kbps side-info на канал —
это другой режим/масштаб, не путать с ~3 кбит на блок classic Auro-Codec.)


------------------------------------------------------------------------------
7. Мета на разных carrier-каналах: общая или автономная?
------------------------------------------------------------------------------

Смешанная модель: синхронизация общая, полезные данные — по каналам свои.

Общее / совместное:
  - Sync lock: SyncDetector OR’ит LSB (и bit2) по всем live carrier-каналам.
  - Common header кадра один на frame.
  - Timeline / sync_sample / block_size общие.
  - Тихий pad (нулевой LFE) выкидывают из OR, иначе ломает sync.

Автономное (per-channel):
  - Свой header: aligned_word / aligned_bit / aligned_code.
  - Свой ParseResult: stream_words + ctx + Golomb-Rice residuals.
  - Extrapolate descriptor на свой frame-channel slot.
  - Битстримы меты НЕ копия одного и того же по FL/FR/… .

Стыковка:

  carrier FL/FR/…  →  OR LSB  →  общий sync + common header
       │
       ├─ FL: свой packed bitstream → ParseResult[FL]
       ├─ FR: свой packed bitstream → ParseResult[FR]
       └─ …
                ↓
           Extrapolate (source PCM из DelayLine + residuals своего канала)

ADOL-сканер layout часто находит мету на одном carrier_channel,
но runtime codec-v3 ждёт per-channel headers у активных слотов.

Итог: каналы не независимы по времени (общий кадр/sync),
но метаданные residuals автономны.


------------------------------------------------------------------------------
8. Классы выходных каналов (native path)
------------------------------------------------------------------------------

  carrier_passthrough — слот есть в WAV, копируется как есть
  native / native_auro — восстановлен GolombRice/Extrapolate из metadata
  auromatic / XinN     — синтетический upmix (не Extrapolate); см. §10

В логе ярлык auromatic иногда ставится и на каналы, которые всё ещё
пришли из Extrapolate (пример Auro 2D: C/LS/RS) — имя ≠ обязательно XinN.


------------------------------------------------------------------------------
9. Extrapolate vs Auro-Matic / XinN
------------------------------------------------------------------------------

Ошибочная модель: «в мете нет residuals → значит height из Auro-Matic по bed».

Правильно — разные режимы:

  Контент                              | Height откуда
  -------------------------------------+----------------------------------------
  Auro-encoded (sync/ADOL + frame      | всегда Extrapolate (GR residuals +
  words для native height)             | params). Residuals могут быть малыми
                                       | /нулевыми после хорошего unmix, но
                                       | путь всё равно Extrapolate.
  Legacy (нет Auro-меты)               | Auro-Matic / XinN — синтетика из bed
  Auro есть, но запрошено больше       | Extrapolate на то, что native отдал
  height-слотов, чем native отдал      | + XinN добивает «дыры»

Схема выбора:

  есть Auro-мета для height? ──да──► Extrapolate (+ residuals)
           │
           нет (legacy) ──► Auro-Matic/XinN из bed
           │
           да, но слотов не хватает ──► Extrapolate + XinN на дыры

Auro-Matic — не «запасной Extrapolate», а другой DSP-upmix:
восстанавливает не авторский height из residuals, а синтезирует height
из уже имеющихся каналов.

В нашем декодере (decoder.cpp) XinN включается примерно когда:
  1. legacy_auromatic_upmix — нет Auro, строим недостающие каналы из carrier;
  2. Auro 13.1 (7.1+5H+T), а native export дал только HL/HR (0x07BF) —
     остальной height (HC/T/…) добивает XinN;
  3. иначе missing height → опционально ASC4HE fallback (часто выключен).

Итог: авторский Auro height всегда через Extrapolate.
Auro-Matic/XinN — для legacy или недостающих слотов, не замена «пустых residuals».
